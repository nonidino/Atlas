# Decoder (Noether 1.1)

**Type:** Concept — model portion (folder: Noether 1.1)
**Status:** Design. The map from evolved tokens back to a physical next-state. Major 1.1 change: the **general increment head is the default**, and **incompressibility is no longer hard-wired** — the div-free-by-construction stream-function decoder of [[noether-1.0-rbc]] §4.7 is retired as the default because it hard-codes a fluid-specific law and is incompatible with compressible flow and with particles. Div-free, where it holds, is now a *discovered* constraint ([[discovered-conservation-1.1]]), not a decoder wiring.

## What it does — intuitively

Read each evolved token and paint the field back into continuous space — at any resolution, because the decoder is coordinate-conditioned (query the token's latent at any point in its patch). It outputs an **increment** (a change to add to the current state), per field, which keeps the map close to identity by construction *only in magnitude* — the increment is where all the dynamics live, and it must be *allowed to be large*, unlike the 1.0-RBC head whose structure quietly favored tiny increments.

The deliberate subtraction: 1.0-RBC decoded a stream function $\psi$ and took a curl, so $\nabla\cdot u=0$ held to machine precision — elegant, but it *is* the assumption "this is an incompressible fluid," baked into the wiring. 1.1 decodes the velocity increment **directly**. Incompressible data will drive the divergence toward zero through the discovered-conservation stage; compressible data will not. The same head serves both — and serves particles, whose "increment" is an acceleration/velocity update with no notion of divergence at all.

## What it does — mathematically

Per field $f$, per node $i$, coordinate-conditioned SIREN heads over the dual latent paths:
$$\delta v^f(y) = \mathrm{Dec}^{f}_{\text{lo}}\big(t_i^{f,(L)},\gamma(y-x_i)\big) + \mathrm{Dec}^{f}_{\text{hi}}\big(h_i^{f,\text{hi}},\gamma(y-x_i)\big),\qquad v^f_{t+1}(y) = v^f_t(y) + \delta v^f(y),$$
for any query $y$ in patch $i$ ([[coordinate-implicit-tokens]]).

**$\gamma(\cdot)$ — why the coordinate is Fourier-encoded, not fed raw.** $y-x_i$ is the offset *relative* to the node's centroid (translation-invariant — shifting the whole system doesn't change it), expanded into a Fourier feature bank $\gamma(\delta)=[\sin(2\pi b_k\delta),\cos(2\pi b_k\delta)]_k$ before entering the network. A plain MLP is biased toward smooth, low-frequency functions (spectral bias); expanding the offset into many sinusoids first gives the network direct access to high-frequency structure from the start — without it, the decoder could not represent a sharp gradient regardless of depth.

**What $\mathrm{Dec}$ actually is — a SIREN, not a generic MLP.** $\mathrm{Dec}(t_i,\gamma(y-x_i))$ concatenates the token latent and coordinate encoding into one input and passes it through layers $\mathrm{layer}(x)=\sin(\omega_0(Wx+b))$, $\omega_0=30$ — chosen because $\sin$ stays smooth and differentiable to arbitrarily high order everywhere (unlike ReLU, whose second derivative is zero almost everywhere), which matters since the decoded field must support the gradients/vorticity the tokenizer computes on it. This needs a matched, non-standard init to train at all — first layer $\sim\mathrm{Unif}(-1/\text{fan\_in},1/\text{fan\_in})$, subsequent layers $\sim\mathrm{Unif}(-\sqrt{6/\text{fan\_in}}/\omega_0,\sqrt{6/\text{fan\_in}}/\omega_0)$, per [[noether-1.0]] §5 — the standard init would make the $\sin$ layers saturate or die.

The high-frequency path $h^{\text{hi}}$ carries near-cutoff content; its *chaotic* part is not decoded deterministically but generated by [[post-decoder-diffusion-1.1]].

- **General head (default).** Direct per-component increment — works for scalars (temperature), vectors (velocity, $\mathbf B$), and particle kinematics (acceleration). No structural constraint.
- **Structure-preserving heads (optional, discovered-gated) — two variants at very different cost.** A **potential/stream-function head** decodes a scalar $\delta\psi=\mathrm{Dec}_\psi(\dots)$ and sets $\delta v=\nabla^\perp\delta\psi=(\partial_y\delta\psi,-\partial_x\delta\psi)$ — divergence-free **identically**, not approximately, since $\nabla\cdot\nabla^\perp\delta\psi=\partial_x\partial_y\delta\psi-\partial_y\partial_x\delta\psi=0$ always (mixed partials commute); cheap — one extra scalar decode plus fixed finite-difference operators. A **Helmholtz-projected head** instead decodes $\delta v$ directly and projects out its divergent part, $\delta v^*=\delta v-\nabla\Delta^{-1}(\nabla\cdot\delta v)$ — the Leray projector — which *also* removes divergence, but $\Delta^{-1}$ is a Poisson solve: a genuinely costly elliptic problem over the whole domain, every time (the same local/pointwise-constraint expense [[discovered-conservation-1.1]] argues for the divergence case). Both variants are engaged **only** when the divergence constraint has been discovered to hold with high confidence ([[discovered-conservation-1.1]]) — an optimization the model earns, not a default it assumes; on data where divergence genuinely isn't zero (compressible flow), neither engages.
- **Boundary conditions** are applied by fixed ghost-stencil overwrites where present (walls, Dirichlet $T$), which are geometric, not physics-law-specific, and so stay in the general path.

## Physics relevance

- **Generality restored.** Removing hard div-free is what re-opens compressible flow, MHD, and particle dynamics to the *same* decoder — the single change most aligned with 1.1's mandate that nothing in the core assume "fluid" ([[00-noether-1.1-overview]]).
- **Increment ≠ near-identity.** Predicting a residual is fine; predicting a *small* residual is the failure. By decoupling the increment head from any energy-shrinking structure and pairing it with a motion-demanding loss, the decoder is allowed to move the state as much as the physics does.
- **Resolution-free output.** Coordinate conditioning means one model trained at $128\times64$ can decode at $512\times256$ — the operator-learning property ([[branch-trunk-operator-tokens]]) the grid-tied baselines lack.

## How fundamental constants are included

- **Re-dimensionalization.** The decoded increment is in nondimensional units; the characteristic scales built from dimensional constants ([[conditioning-and-constants-1.1]]) map it back to physical units — the mirror of the tokenizer's ruler step. This is the decoder's only *direct* contact with dimensional constants.
- **No constant is hard-coded in a head.** The choice of decode mode (general vs. structure-preserving) is gated by *discovered* constraints, which are themselves conditioned on the constants — so e.g. "use the div-free head" is reached only when the data (at this $\mathrm{Ma}$, this regime) actually supports it.
- **Vector-constant awareness** is inherited from the token (the covariant channel), not re-introduced at decode.
